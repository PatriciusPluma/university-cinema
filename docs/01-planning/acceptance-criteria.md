# Критерии приёмки пользовательских историй кинотеатра

Критерии определяют, при каком наблюдаемом результате история считается выполненной. Источник формулировок и названий задач — [бэклог](backlog.md), порядок соответствует [карте историй](story-map.png). Для каждой задачи приведены два сценария в формате «Дано / Когда / Тогда»: основной и граничный либо отказной. Название раздела совпадает с названием задачи в бэклоге.

## Путь зрителя

### Посмотреть афишу

1. **Дано:** в каталоге опубликованы фильмы; **Когда:** зритель открывает афишу; **Тогда:** он видит список опубликованных фильмов с названиями и обложками.
2. **Дано:** фильм не опубликован; **Когда:** зритель открывает афишу; **Тогда:** этот фильм в списке не отображается.

### Изучить описание фильма

1. **Дано:** фильм опубликован; **Когда:** зритель открывает его карточку; **Тогда:** он видит название, описание, длительность и возрастное ограничение.
2. **Дано:** карточка фильма не существует; **Когда:** зритель открывает её адрес; **Тогда:** он видит сообщение «Фильм не найден», а данные другого фильма не показываются.

### Посмотреть доступные фильмы

1. **Дано:** у опубликованного фильма есть будущий сеанс, открытый для продажи; **Когда:** зритель открывает список доступных фильмов; **Тогда:** фильм присутствует в списке.
2. **Дано:** у фильма нет будущих сеансов, открытых для продажи; **Когда:** зритель открывает список доступных фильмов; **Тогда:** фильм не предлагается для выбора сеанса.

### Выбрать дату

1. **Дано:** у выбранного фильма есть сеансы на несколько дат; **Когда:** зритель выбирает дату; **Тогда:** он видит сеансы только на эту дату.
2. **Дано:** на выбранную дату нет доступных сеансов; **Когда:** зритель выбирает её; **Тогда:** система сообщает, что сеансов на эту дату нет, и не предлагает прошедшие сеансы.

### Выбрать время сеанса

1. **Дано:** на выбранную дату есть несколько будущих сеансов фильма; **Когда:** зритель открывает расписание; **Тогда:** он видит время начала каждого сеанса и может выбрать одно из них.
2. **Дано:** сеанс уже начался или закрыт для продажи; **Когда:** зритель просматривает расписание; **Тогда:** он не может выбрать этот сеанс для новой покупки.

### Изучить схему зала

1. **Дано:** для сеанса назначен зал со схемой мест; **Когда:** зритель открывает схему; **Тогда:** он видит расположение рядов и номера мест.
2. **Дано:** в зале есть проходы или отсутствующие места; **Когда:** зритель открывает схему; **Тогда:** они не отображаются как доступные для выбора места.

### Посмотреть свободные места

1. **Дано:** на сеансе есть свободные и занятые места; **Когда:** зритель открывает схему; **Тогда:** свободные места визуально отличаются от занятых и доступны для выбора.
2. **Дано:** место только что было куплено другим зрителем; **Когда:** зритель обновляет доступность; **Тогда:** место больше не показывается свободным.

### Освободить места после истечения времени оплаты

1. **Дано:** срок удержания мест истёк, а заказ не оплачен; **Когда:** система обновляет доступность мест; **Тогда:** места снова доступны другим зрителям.
2. **Дано:** оплата подтверждена до истечения срока удержания; **Когда:** наступает время его окончания; **Тогда:** оплаченные места не освобождаются для повторной продажи.

### Выбрать и удержать места

1. **Дано:** место свободно; **Когда:** зритель выбирает его для оформления; **Тогда:** место удерживается за его заказом на ограниченное время, а зритель видит срок удержания.
2. **Дано:** два зрителя одновременно пытаются удержать одно место; **Когда:** система обрабатывает запросы; **Тогда:** удержание получает только один из них, а второй видит, что место уже недоступно.

### Исключить двойную продажу места

1. **Дано:** для места на сеансе уже есть действительный оплаченный билет; **Когда:** другой заказ пытается завершить покупку того же места; **Тогда:** второй действительный билет не создаётся.
2. **Дано:** подтверждение одного платежа пришло повторно; **Когда:** система повторно обрабатывает его; **Тогда:** количество билетов на оплаченные места не увеличивается, а состояние заказа остаётся корректным.

### Проверить стоимость

1. **Дано:** зритель выбрал места на сеансе; **Когда:** он открывает заказ до оплаты; **Тогда:** он видит цену каждого билета и итоговую сумму.
2. **Дано:** цена сеанса изменилась после создания заказа; **Когда:** зритель повторно открывает действующий заказ; **Тогда:** ранее подтверждённая сумма заказа не изменяется без нового подтверждения зрителя.

### Оформить заказ

1. **Дано:** выбранные места удерживаются за зрителем; **Когда:** он подтверждает сеанс и места; **Тогда:** создаётся заказ с правильными фильмом, датой, временем, местами и суммой.
2. **Дано:** срок удержания одного из мест истёк; **Когда:** зритель подтверждает оформление; **Тогда:** заказ с недоступным местом не создаётся, а зритель получает предложение выбрать места заново.

### Оплатить заказ

1. **Дано:** действующий неоплаченный заказ существует; **Когда:** платёжная система подтверждает успешную оплату; **Тогда:** заказ получает статус «Оплачен», а купленные места больше не доступны для продажи.
2. **Дано:** платёж отклонён; **Когда:** зритель возвращается к заказу; **Тогда:** заказ не помечается оплаченным, билет не выдаётся и отображается понятный результат попытки.

### Получить подтверждение покупки

1. **Дано:** оплата заказа подтверждена; **Когда:** зритель открывает результат покупки; **Тогда:** он видит подтверждение с номером заказа, суммой и сведениями о сеансе.
2. **Дано:** оплата не завершилась успешно; **Когда:** зритель открывает результат попытки; **Тогда:** сообщение об успешной покупке не показывается.

### Открыть электронный билет

1. **Дано:** оплата подтверждена и зритель вошёл в свой личный кабинет; **Когда:** он открывает раздел билетов не позднее одной минуты после подтверждения; **Тогда:** видит электронный билет с фильмом, сеансом, залом, рядом и местом.
2. **Дано:** билет принадлежит другому зрителю; **Когда:** пользователь пытается открыть его из своего кабинета; **Тогда:** доступ запрещён и данные чужого билета не раскрываются.

## Путь администратора

### Создать карточку фильма

1. **Дано:** администратор ввёл обязательные данные фильма; **Когда:** он сохраняет и публикует карточку; **Тогда:** фильм появляется в афише с сохранёнными данными.
2. **Дано:** обязательное название фильма не указано; **Когда:** администратор пытается сохранить карточку; **Тогда:** система показывает ошибку и фильм не публикуется.

### Изменить карточку фильма

1. **Дано:** карточка фильма существует; **Когда:** администратор изменяет описание и сохраняет его; **Тогда:** зрители видят новое описание в карточке фильма.
2. **Дано:** администратор отправил недопустимые данные; **Когда:** он пытается сохранить изменения; **Тогда:** система показывает ошибку, а прежняя карточка остаётся без изменений.

### Удалить карточку фильма

1. **Дано:** у фильма нет будущих сеансов и связанных продаж; **Когда:** администратор подтверждает удаление; **Тогда:** фильм больше не отображается в афише.
2. **Дано:** у фильма есть будущий сеанс или проданные билеты; **Когда:** администратор пытается удалить карточку; **Тогда:** система не удаляет данные, необходимые для существующих заказов, и объясняет причину отказа.

### Создать зал

1. **Дано:** администратор задал название зала, ряды и места; **Когда:** он сохраняет зал; **Тогда:** зал появляется в списке и его схема доступна при создании сеанса.
2. **Дано:** в одном ряду два места с одинаковым номером; **Когда:** администратор сохраняет схему; **Тогда:** система отклоняет её и указывает на повторяющийся номер.

### Изменить параметры зала

1. **Дано:** зал не используется сеансом с проданными билетами; **Когда:** администратор изменяет название или схему и сохраняет её; **Тогда:** обновлённые параметры отображаются при следующем просмотре зала.
2. **Дано:** на место уже продан билет будущего сеанса; **Когда:** администратор пытается удалить это место из схемы; **Тогда:** система не допускает изменение, которое сделало бы билет некорректным.

### Удалить зал

1. **Дано:** у зала нет будущих сеансов и связанных продаж; **Когда:** администратор подтверждает удаление; **Тогда:** зал больше нельзя выбрать для нового сеанса.
2. **Дано:** в зале есть будущий сеанс или проданные билеты; **Когда:** администратор пытается удалить зал; **Тогда:** система сохраняет связанные данные и показывает причину отказа.

### Создать сеанс

1. **Дано:** фильм и зал существуют, а время свободно; **Когда:** администратор сохраняет новый сеанс; **Тогда:** сеанс появляется в расписании с заданными фильмом, залом, датой и временем.
2. **Дано:** в том же зале уже есть пересекающийся по времени сеанс; **Когда:** администратор пытается сохранить новый; **Тогда:** система отклоняет его и сообщает о конфликте расписания.

### Изменить параметры сеанса

1. **Дано:** на сеанс ещё не проданы билеты; **Когда:** администратор меняет дату или время; **Тогда:** расписание показывает обновлённые данные.
2. **Дано:** изменение создаёт пересечение с другим сеансом в том же зале; **Когда:** администратор пытается его сохранить; **Тогда:** система отклоняет изменение и сохраняет прежнее расписание.

### Отменить сеанс

1. **Дано:** будущий сеанс открыт для продажи; **Когда:** администратор отменяет его; **Тогда:** сеанс получает статус «Отменён» и больше не доступен для новой покупки.
2. **Дано:** на отменённый сеанс уже есть заказы; **Когда:** администратор открывает их список; **Тогда:** заказы и билеты остаются видимыми с отметкой об отмене сеанса, а не исчезают из истории.

### Установить и изменить цены

1. **Дано:** администратор назначил положительную цену билета на сеанс; **Когда:** зритель выбирает место; **Тогда:** он видит установленную стоимость до оформления заказа.
2. **Дано:** цена сеанса изменена после создания заказа; **Когда:** ранее созданный заказ открывается повторно; **Тогда:** сохранённая в заказе сумма не пересчитывается автоматически.

### Просматривать заказы

1. **Дано:** у сеанса есть оформленные заказы; **Когда:** администратор открывает список заказов; **Тогда:** он видит номер, места, сумму и статус каждого заказа.
2. **Дано:** пользователь без роли администратора запрашивает список заказов; **Когда:** система проверяет его доступ; **Тогда:** она не раскрывает данные заказов.

### Просматривать статусы билетов

1. **Дано:** у сеанса есть билеты; **Когда:** администратор открывает их список; **Тогда:** он видит статус каждого билета и связанный с ним заказ.
2. **Дано:** билет связан с неоплаченным заказом или отменённым сеансом; **Когда:** администратор проверяет его статус; **Тогда:** билет не показывается как действительный.

### Отслеживать продажи

1. **Дано:** за выбранный период есть оплаченные заказы; **Когда:** администратор открывает сводку продаж; **Тогда:** он видит количество проданных билетов и общую сумму за этот период.
2. **Дано:** за период есть неоплаченные заказы; **Когда:** администратор открывает сводку; **Тогда:** они не увеличивают число проданных билетов и сумму выручки.
